# 製品に CLI・モデル・文書管理の規範・スキル・欠陥運用の規範を含める

- ステータス: stable
- 日付: 2026-11-17
- 関連: GitHub Issue #4
- 起点: 2026-11-17 の grilling（Q4）で確定

## 背景

文書管理の仕組みを製品として切り出すにあたり、CLI とモデルのほかに、規範・スキル・欠陥運用・
DoD が候補に挙がっていた。規範は quality item として書かれ、ID・ADR・risk の採点・テスト系
item の粒度・鮮度など文書管理の決まりを述べるものと、開発の進め方（コメント規約や整形など）を
述べるもの、特定の製品に結びついたものが混ざっていた。DoD の様式は、別のスキル（def-done）が
持っている。製品に何を含めるかを決める必要があった。

## 決定

製品は、CLI とモデルに加え、文書管理の規範（quality 14 本）、スキル、欠陥運用の規範を含める。
開発の進め方の規範、特定の製品に結びついた規範、DoD は含めない。

スキルの本数と名前はこの ADR では決めない。スキルの範囲は GitHub Issue #46 で決める。

## 根拠

規範は CLI の検査の根拠である。切り離すと、検査が何を守るのかを説明できない。

スキルは CLI の出力の形を前提にしている。CLI と同じバージョンで配るほうが、スキルと CLI が
食い違わない。

欠陥運用は「起票の時点で既存の risk か test_condition に辿れたか」を数えるもので、risk を
中心に置く concept に沿う。

開発の進め方の規範と特定の製品に結びついた規範は、文書管理の機構ではない。DoD は def-done
スキルの持ち物で、文書管理の機構とは別である。

## 棄却した代替案

### 規範だけを含め、スキルと欠陥運用は後に回す

スキルを CLI と別に配ることになり、スキルが前提にする CLI の出力の形と食い違いうる。
欠陥運用も、risk を中心に置く concept に沿う仕組みでありながら製品から外れる。

### CLI とモデルのほかは何も加えない

規範を切り離すことになり、CLI の検査が何を守るのかを説明できない。

### DoD も含めて全部を含める

DoD は def-done スキルの持ち物で、文書管理の機構とは別である。開発の進め方の規範と特定の
製品に結びついた規範も、文書管理の機構ではない。
