# 利用者向けのスキルを公開用として英語で書く

- ステータス: stable
- 日付: 2026-11-21
- 関連: GitHub Issue #4
- 起点: 2026-11-17 の grilling（Q20）で確定し、2026-11-21 に配り方を改めた

## 背景

製品に含めるスキルを、どこに置いて、どの名前で、どう配るかを決める必要があった。2026-11-17 の
grilling では、スキルを mitodoke のリポジトリに置いて mitodoke の flake の出力として配り、名前を
`mitodoke-docs`・`mitodoke-test-plan`・`mitodoke-test-analyze` にすると決めた。

その後、mitodoke 自身の開発で使うスキル 3 本（`sara-docs`・`term-record`・`term-apply`）を
`dev/skills/` に置いた（Issue #44）。どれも暫定で、日本語で書いてあり、写した shell script の
名前でコマンドを呼んでいる。用語のスキルは、2026-11-17 の決定のあとに加わったものである。

2026-11-21 に、利用者向けのスキルを公開用として英語で用意することを決め、その作業を Issue #46 に
分けた。スキルの範囲・名前・置き場所・配り方は、#46 の着手時の論点として残っている。

## 決定

- 利用者向けのスキルは、公開用として英語で書く
- `dev/skills/` の日本語のスキルは、CLI が機能するまでの暫定とする
- 配り方は、プラグインやマーケットプレイスと、mitodoke の flake の出力を候補とし、どちらか、
  または両方を持つかを Issue #46 で決める
- 公開するスキルの範囲と名前、置き場所も Issue #46 で決める

## 根拠

利用者向けのスキルは、利用者が自分のリポジトリで使うもので、文書のモデルの構造を知ったうえで
CLI を使う手順をエージェントに与える。`dev/skills/` の日本語のスキルは、mitodoke 自身の開発のための
暫定のもので、CLI のサブコマンドではなく写した shell script の名前でコマンドを呼んでいる。

配り方の候補を ADR に残しておくと、#46 の着手時に、どこまで決まっているかが分かる。flake の出力が
候補に残るのは、CLI と同じリポジトリと flake で配れば、CLI とスキルのバージョンが揃うからである。

## 棄却した代替案

### 2026-11-17 の決定のまま、置き場所・名前・配り方を決める

スキルを mitodoke のリポジトリに置いて flake の出力として配り、名前を `mitodoke-docs` などにする
案。2026-11-21 に配り方を改め、置き場所と名前も #46 の論点に戻ったので、改める前の内容を決定として
残さない。

### プラグインとマーケットプレイスで配ることを決定にする

#46 の本文は「プラグインやマーケットプレイスの形で提供する」と書いているが、flake の出力と両方を
持つかは、#46 の論点として残っている。そのため、決定ではなく候補として書く。

### いまの日本語のスキルを公開用のスキルとして使う

`dev/skills/` の日本語のスキルは暫定で、写した shell script の名前でコマンドを呼んでいる。日本語版も
あわせて公開するかは、#46 で決める。
