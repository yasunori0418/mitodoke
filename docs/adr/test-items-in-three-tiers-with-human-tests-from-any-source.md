# テスト系 item を CASE・TC・RISK の 3 段で起こし、人が行うテストも CASE にして、手順書とテストチャーターは列挙のコマンドからも一覧に載せる

- ステータス: stable
- 日付: 2026-11-24
- 関連: [テスト系 item を CASE・TC・RISK の 3 段で起こし、人が行うテストも CASE にする](test-items-in-three-tiers-with-human-tests.md), [test_condition に、人が最終的に判断する理由の human_judgement を持たせる](test-condition-human-judgement.md), [テスト資産の列挙は内蔵せず、設定のコマンドかコミットしたファイルから読む](test-assets-listed-by-configured-sources.md), GitHub Issue #75, GitHub Issue #80, `dev/tests/test-doc-map.sh`
- 起点: issue #75 の grilling（2026-11-24）で確定。#80 で決めた ADR を、手順書とテストチャーターを一覧に載せる出どころだけを変えて書き直した

## 背景

テスト系 item を CASE・TC・RISK の 3 段で起こし、人が行うテストも CASE にする決定（#80）は、手順書と
テストチャーターを、コミットした一覧のファイルからだけテスト資産の一覧に載せるとしていた。

一覧のファイルは人が 1 行ずつ書くので、手順書を追加したのに一覧へ書き忘れることがある。

ほかのテスト資産は設定に書いた列挙のコマンドの出力からも一覧に載せられるが、手順書とテストチャーターは
載せられなかった。

## 決定

- CASE はテストファイル・e2e シナリオ・flake check の単位で起こし、テスト関数の単位には割らない。
  CASE とテスト資産を 1 対 1 にする
- 人が行うテストも CASE として起こし、`resource` で手順書かテストチャーターのファイルを指す。`covers` と
  `follows` の必須は保つ
- [テスト資産](../ubiquitous-language/test-asset.md)の定義から「単独で実行できる」を外し、手順書と
  テストチャーターのファイルを含める。手順書とテストチャーターも、ほかのテスト資産と同じく、設定に書いた
  列挙のコマンドの出力か、コミットした一覧のファイルからテスト資産の一覧に載せる。種別は手順書と
  テストチャーターの 2 つの値で表す
- 手順書とテストチャーターの置き場所は設定に持たず、製品が自分で決める
- テストの実施の記録はグラフに置かない
- TC は検証テーマの単位で起こし、同じ不変条件・観点を検証する CASE 群を束ねる
- RISK は TC を束ねる脅威の単位で起こし（対象あたり 2〜5 件）、`requirement` / `design` への
  `threatens` で表す
- テストレベルとテストタイプは組み込みのモデルに入れない

## 根拠

テスト資産の単位にする根拠は、CASE と資産が 1 対 1 になり、資産の追加やリネームに CASE が追従して
いるかを契約テストで確かめられることにある。人が行うテストも手順書かテストチャーターのファイルを資産に
すれば、同じ 1 対 1 の確かめ方がそのまま使える。

一覧のファイルは人が 1 行ずつ書くので、手順書を追加して書き忘れると、`test_case` の無い手順書を検査が
見つけられない。列挙のコマンドを使えれば、置き場所の下のファイルを毎回並べ直せる。

mitodoke がテスト資産の列挙を内蔵しないことは
[テスト資産の列挙は内蔵せず、設定のコマンドかコミットしたファイルから読む](test-assets-listed-by-configured-sources.md)
で決めてあり、この ADR はそれを変えない。手順書とテストチャーターも、この決定に沿って列挙のコマンドか
一覧のファイルから一覧に載せる。

実施の記録は出来事で、グラフが持つのは規範である。記録をグラフに置くと、実施のたびに item が変わり、
鮮度の比較に使えなくなる。

## 棄却した代替案

### テスト関数の単位で CASE を起こす

CASE が 200 件を超え、ファイル単位のテスト資産とも 1 対 1 にならない。

### 人が行うテストを CASE にせず、test_condition の散文に書く

人が行うテストだけが `covers` と `follows` を持たず、`test_plan` から辿れなくなる。

### 人が行うテストに新しい型を設ける

型は 12 のまま増やさない。手順書とテストチャーターも、テスト資産として CASE が指せる。

### 設定に置き場所を持ち、mitodoke がその下のファイルを並べる

テスト資産の列挙を内蔵しない決定に反する。

### 設定に置き場所を持ち、`check` が資産の場所だけを確かめる

置き場所のディレクトリを作る手段が無く、設定の値の使い道が小さい。
