# 人の識別子は、設定に定義したコマンドの出力から取る

- ステータス: stable
- 日付: 2026-11-17
- 関連: GitHub Issue #4
- 起点: 2026-11-17 の grilling（Q28）で確定

## 背景

[verify は、端末で人が確認を入力したときだけ確認の記録を書く](verify-records-human-only-from-terminal.md) で、
`mitodoke verify` は端末で人が確認したときだけ `human:<id>` を書くと決めた。この `<id>` をどこから取るかは
決めていなかった。

`human:<id>` は文書に残ってコミットされる。git の `user.name` は自由な文字列で、空白を含む本名を
設定している人もいる。git の設定はリポジトリごとにも利用者全体にも書けるが、どちらもリポジトリには
コミットされない。

## 決定

`mitodoke.yaml` に、`<id>` を取るコマンドを定義する（例: `gh api user --jq .login`、`git config user.name`）。
`mitodoke verify` は TTY の確認のあと、そのコマンドを利用者の環境で実行し、出力を `human:<id>` の `<id>` にする。
出力が空・複数行のとき、`"`・`\`・改行を含むとき、コマンドが失敗したときは、何も書かずにエラーにする。

コマンドは設定ファイルに書いてコミットするのでプロジェクトで共通だが、実行は利用者ごとの環境で
行うので、結果は利用者ごとに変わる。

定義と検証の内容は [人の確認に書く識別子は設定のコマンドの出力から取り、不正な出力では何も書かない](../requirements/human-id-command.md) が定める。

## 根拠

- git の設定のような特定の取り方を読むのではなく、取得のコマンドを設定に定義すれば、`gh` コマンドで GitHub のアカウントの ID を取ることも、git の設定から利用者の名前を取ることもできる。どちらで取るかをプロジェクトが選べる
- `"`・`\`・改行は、YAML の二重引用符の中にそのまま書けない。空や複数行の出力、コマンドの失敗では `<id>` が決まらない。これらのときは何も書かずにエラーにして、書けない値や決まらない値を記録に残さない

## 棄却した代替案

### 利用者ごとの git の設定の専用のキーから取る

利用者ごとの git の設定（`mitodoke.humanId` のような専用のキー）から取り、設定が無ければ書かずに
エラーにする案。何を書くかを利用者自身が明示して決められるが、わざわざ git の設定のキーを読ませるより、
取得のコマンドを設定に定義するほうが、GitHub のアカウントの ID と git に設定した名前のどちらにも
対応できるので採らなかった。

### git の user.name から取る

git の `user.name` を `<id>` にする案。`user.name` は自由な文字列なので、本名やほかの用途の名前が、
意図せずコミットされる文書に残りうる。このため採らなかった。

### 実行のたびに引数で渡す

実行のたびに `--as <id>` のような引数で渡す案。実行のたびに入力が要り、打ち間違えると同じ人が別の ID で
記録されるので採らなかった。
