# ループの右側には型も relation も足さず、既存の型に規範を置く

- ステータス: stable
- 日付: 2026-11-22
- 関連: GitHub Issue #80, `docs/model.yaml`
- 起点: issue #80 の grilling（2026-11-22）で確定

## 背景

ホリスティックテスティングは開発の流れを Discovery から Learning までの 1 つのループとして描く。ループの右側には、デプロイ・リリース・観測（Observability）・学習（Learning）がある。コンセプトの §10 はホリスティックテスティングに沿うと宣言しているが、ループの右側に当たるものをモデルのどこに置くかは決まっていなかった。

ISTQB の Foundation Level は、本番環境でのテストに触れていない。ループの右側の根拠はホリスティックテスティングだけである。

## 決定

- ループの右側のために、型も relation も足さない。型は 12 のまま保つ
- 観測できること（計装、警告の出力）は、満たすべき振る舞いとして `requirement` に置く
- デプロイやリリースで行うテストは `test_case` として起こし、従う `test_plan` へ `follows` を張る
- 利用者のフィードバックを受けて上流を読み直す手順は、`quality` の規範に置く
- 観測の結果、テストの実行の記録、受け取ったフィードバックそのものはグラフの外に置く

## 根拠

グラフが持つのは規範で、出来事は持たない。ループの右側で生じるもののうち、規範に当たるのは、何を観測できるようにするか、どのテストをどこで行うか、フィードバックをどう扱うか、の 3 つで、どれも既存の型で書ける。観測の結果や実行の記録は出来事なので、グラフに置かない。

## 棄却した代替案

### 観測やリリースの結果を持つ型を足す

結果は出来事で、時間とともに増え続ける。グラフに置くと、規範の鮮度の比較に使えなくなる。

### フィードバックを表す relation を足す

フィードバックを上流へ戻すのは人が行う手順で、規範として `quality` に書ける。relation にすると、受け取ったフィードバックという出来事を item にしなければならない。
