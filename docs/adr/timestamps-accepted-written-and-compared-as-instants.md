# 時刻は UTC オフセット付きで受け付けてローカルのオフセットで書き、時刻として比べる

- ステータス: stable
- 日付: 2026-11-23
- 関連: GitHub Issue #74
- 起点: issue #74 の grilling（2026-11-23）で確定

## 背景

`generated.at` と `verified[].at` の時刻は、受け付ける書式、`new` と `verify` が書く書式、鮮度を比べる
ときの読み方が決まっていなかった。写した `okf-frontmatter` は UTC オフセット付きの ISO 8601 を受け付ける。
写した `sara-fresh` は時刻を文字列のまま比べるので、オフセットの違う時刻を並べると順序を誤る。今の
item の時刻は、どれもローカルのオフセットで書かれている。

## 決定

- 受け付ける時刻は、UTC オフセット付きの ISO 8601 とし、小数の秒と `Z` も受け付ける。現在時刻より先の
  `generated.at` と `verified[].at` は違反にする
- 書くときは、実行した環境のローカルの UTC オフセットを付けた、秒までの形にする（例
  `2026-11-23T13:45:23+09:00`）。`new` と `verify` で同じ形にする
- 比べるときは、文字列ではなく時刻として読む。`generated.at` の表記だけを書き換えて同じ時刻を指して
  いるときは、変わっていないとみなす

## 根拠

受け付ける書式を写した `okf-frontmatter` と同じにすれば、今の item をそのまま読める。現在時刻より先の
時刻は、書いた時刻の記録として成り立たず、鮮度の比較で上流を常に新しく見せる。

書く形をローカルのオフセットにすれば、今の item の時刻と同じ形になり、人が読むときに換算が要らない。
`new` と `verify` で同じ形にすれば、2 つの記録を並べて読める。

時刻として読んで比べれば、オフセットの違う時刻を並べても順序を誤らない。表記だけの書き換えを変更と
みなさないのも、同じ理由である。

## 棄却した代替案

### 書く時刻を UTC（`Z`）に固定する

文字列のまま比べても順序が合うが、今の item の時刻はすべてローカルのオフセットで書かれていて、人が読む
ときに換算が要る。
