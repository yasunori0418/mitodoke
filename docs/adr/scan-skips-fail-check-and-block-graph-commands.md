# 読み飛ばしは check を失敗させ、グラフを読むほかのサブコマンドを止める

- ステータス: stable
- 日付: 2026-11-23
- 関連: [構造の契約は失敗、つながりの欠けと見直しの義務は報告を既定にし、それぞれの列挙を閉じる](default-strength-with-closed-lists.md), GitHub Issue #74
- 起点: issue #74 の grilling（2026-11-23）で確定

## 背景

sara-core は、必須のキーが欠けたファイルと、enum の範囲外の値を持つファイルを、エラーにせず読み飛ばす
（scan warning）。issue #73 の調査で、sara-core の検証（`check_items`）は読み飛ばしを受け取らないことが
分かった。読み飛ばしたファイルを除いたグラフで検査や報告を進めると、欠けた結果を出す。

一方で、検査の既定の強さは、3 つの分類（構造の契約・つながりの欠け・見直しの義務）に当たる検査を閉じた
列挙で決め、どの検査の強さも設定で変えられるとしている。読み飛ばしをこの列挙のどこに置くか、あるいは
置かないかを決める必要があった。

## 決定

読み飛ばしは、検査ではなく、読み込みが成り立つための前提として扱い、強さの設定の対象にしない。

- `check` では、読み込みの前提が成り立っていないこととして exit 1 にし、読み飛ばしたファイルを、専用の
  コードを付けた `failed` の item で表す
- 読み飛ばしは、検査の 3 つの分類のどれにも入れず、構造の契約の一覧は変えない
- ドキュメントグラフを読み込むほかのサブコマンド（`new`・`index`・`gap`・`fresh`・`matrix`・`verify`・
  `export`）は、読み飛ばしが 1 つでもあれば処理を始めず、入力の誤りとして exit 2 で終える。`new` と
  `verify` も書き込みを拒む

## 根拠

`check` は検査の結果を並べるサブコマンドなので、読み飛ばしたファイルを item にすれば、どのファイルが
なぜ読めないかを、ほかの違反と同じ形で読める。

ほかのサブコマンドは、読めないファイルを除いたグラフで動くと、欠けた結果を出す。`new` と `verify` は、
読めないファイルのあるグラフに書き加えると、relation の先の item が実在するかを確かめられない。

読み飛ばしを検査ではなく前提として扱えば、「どの検査の強さも設定で変えられる」という既定の強さの決定と
食い違わない。そのため、既定の強さの ADR は置き換えず、構造の契約の一覧も変えない。

## 棄却した代替案

### 読み飛ばしを、どのサブコマンドでも exit 2 にする

扱いは 1 通りになるが、`check` が、どのファイルがなぜ読めないかを、ほかの違反と並べて出せなくなる。

### 読み飛ばしも検査の 1 つにして、強さを設定で変えられるようにする

規範は 1 通りになるが、報告に下げると、読めないファイルを除いたグラフで `gap` や `fresh` が動き、欠けた
結果を出す。

### `new` と `verify` を対象から外し、読み飛ばしがあっても書き込めるようにする

関わりの無いファイルの誤りで起票が止まらなくなるが、読み飛ばされた item を指す relation を見逃す。
