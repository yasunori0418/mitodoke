# 自分の製品に導入し、構成に合わせて設定する

## 使われ方

利用者は、自分が開発する製品のリポジトリに mitodoke を導入し、そのリポジトリの文書の構成と
運用に合わせて設定する。適用先の製品が使うプログラミング言語・テストフレームワーク・
アプリケーションアーキテクチャは製品ごとに違い、利用者はそれを変えずに導入する。利用者が
すでに使っている CI やテストランナーも、置き換えずにそのまま使い続ける。

導入したあとも、品質に対する責任は利用者に残る。mitodoke は品質を重視する運用を支援するが、
利用者がレビューの手順を守らないときに、その運用を代わりに有効にはしない。

## この使われ方が要求すること

- 特定のプログラミング言語・テストフレームワーク・アプリケーションアーキテクチャを持つ製品に
  限らず導入できること。
- 適用先の製品の文書の構成と運用に合わせて設定できること。
- 利用者がすでに使っている CI やテストランナーを置き換えずに導入できること。
- 責務を、成果物の構造化・関係の検査・レビューを促す情報の提供に限り、アプリケーションの実装を
  取り込まないこと。
- 品質の判断と確認の遂行を、製品が利用者に代わって引き受けないこと。
- Nix flake で入手でき、組み込む sara-core と同じタグの sara の CLI を一緒に受け取れること。
- 製品として、CLI、モデル、文書管理の規範、欠陥運用の規範、スキルを受け取れること。
- 製品の名前を含む名前がすべて製品の名前 mitodoke から導かれていること。
- 設定を YAML の 1 つの設定ファイルに書け、独自の型・relation・フィールドを sara の model.yaml と同じ書き方で
  追加できること。
- 組み込みの型・relation・フィールドは、設定で削除も変更もできないこと。
- テストの区分を設定の 1 つの一覧で決め、テスト系の item の置き場所と見出しをその一覧から導けること。
- model.yaml と sara.toml を設定ファイルから生成し、生成し直した結果との差分が無いことを確かめられること。
