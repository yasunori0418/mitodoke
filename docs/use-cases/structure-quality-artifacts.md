# 品質に関わる成果物を item として起こし、関係を張る

## 使われ方

利用者は、開発の過程で品質について検討・判断した結果を、要件・設計・リスク・テスト条件・
テスト計画・テストケースといった成果物として書き残す。成果物は 1 つずつ型の付いた item として
起こし、ある成果物がどの成果物を前提にしているかという関係を relation として明示する。

item は人間が書いてもよく、AI を活用したワークフローで書いてもよい。どちらの場合も、目的は
文書をそろえることではなく、開発とテストの背後にある判断を後から確認・追跡できるようにする
ことである。item の中身が妥当であることには、誰が書いたかによらず人間が責任を持つ。

## この使われ方が要求すること

- 品質に関わる成果物を、型の決まった item として起こせること。
- 成果物の間の関係を、種類の付いた relation として item に明示できること。
- 起票・検査・生成を、1 つの CLI のサブコマンドで行えること。
- 組み込みの 12 の型と、型の間の組み込みの relation を、どの適用先の製品でも使えること。
- `specification` を英語で書き、設定で選んだほかの言語の `specification` と題も持てること。
- 起票のときに置き場所が型ごとの置き場所と合うかを確かめ、合わない起票を拒めること。
