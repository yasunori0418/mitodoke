# テスト実行基盤やログ集約基盤になる

> **棄却**: この提案は採らない。mitodoke は汎用的なテストランナーや CI ログ管理システムにならない。実行の記録は
> ホスティングサービスの CI のログに任せ、テストランナーの管理は適用先の製品に残す。決定は
> [コンセプト文書](../mitodoke-concept.ja.md)の「9. CI とテスト実行」と「10. スコープと非目標」にある。

## 提案した使われ方

利用者は適用先の製品のテストを mitodoke から実行し、テストランナーの管理を mitodoke に任せる。テストの実行の
記録とログは mitodoke に集め、どのテストがいつ実行されて成功したかを mitodoke で確かめる。

## 作らない理由

mitodoke の中心的な目的は、テスト実行に意味を持たせるためのテスト意図を、人間が定義し、追跡できるように
することである。テスト実行基盤やログ集約基盤になることは、コンセプト文書が非目標に挙げている。実行の記録は
ホスティングサービスが提供する CI のログで足り、mitodoke はそれを信頼する。

テストランナーの管理を取り込むと、利用者がすでに使っているテストランナーを置き換えることになる。mitodoke の
責務は成果物の構造化・関係の検査・レビューを促す情報の提供に限る。
