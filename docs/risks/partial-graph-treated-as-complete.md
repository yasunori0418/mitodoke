# 読み飛ばされたファイルやモデルを読めないことを見逃し、欠けたグラフのまま検査や書き込みを続ける

## リスク

sara-core の読み込みがファイルを読み飛ばしたこと（scan warning）や、モデルを読めないことを見逃し、
欠けたドキュメントグラフを完全なものとして扱う懸念である。
[検査の既定の強さは、構造の契約を失敗、つながりの欠けと見直しの義務を報告とし、設定で変えられる](../requirements/default-inspection-strength.md)
は、これらを検査ではなく読み込みの前提として扱うことを求める。失敗の向きは次の 3 つある。

- `check` が読み飛ばしを failed の item にせず、exit code 0 で終わる
- `new`・`index`・`gap`・`fresh`・`matrix`・`verify`・`export` が exit code 2 で止まらず、欠けたグラフで
  報告を出すか、`new` と `verify` が書き込む
- モデルを読めないときに組み込みの型へ戻り、適用先の独自の定義を無視して検査する

最も重い向きは、欠けたグラフのまま `new` と `verify` が書き込む向きで、この risk はこの向きで採点する。
読み飛ばされたファイルは item の集合から黙って消えるので、つながりの欠けも再確認待ちも少なく出るだけで、
誤りとしては目に見えない。

[ドキュメントグラフの読み込みを 1 つの結果にまとめる](../design/unified-graph-loading.md) への辺は、
読み飛ばしを失敗にする判定を、読み込みを 1 つにまとめるモジュールの 1 か所に置く設計に固有の面を指す。
この判定がそのモジュールから漏れると、それを経由しないサブコマンドだけが読み飛ばしを見逃す。サブコマンド
ごとに判定を持つ設計へ差し替えれば、この面は消え、代わりに判定の書き漏らしという別の懸念になる。

## 実現性

likelihood は high とした。変わりやすさは高い。扱いが `check` とほかの 7 つのサブコマンドで分かれ、
書き込む 2 つのサブコマンドには拒む規則が加わり、`init` と `model` は対象から外れるので、分岐が多い。
見逃しやすさも高い。写した契約テスト（`dev/tests/` の shell script）は、読み飛ばしとモデルを読めない
場合をどれも確かめていない。

impact は medium とした。欠けたグラフで書いた item や報告は誤っているが、読み飛ばしの原因を直して
再実行すれば回復できる。書き込まれた item も git の差分に残るので、取り消せる。

この採点は CLI のコードが無い時点での読み替えによるもので、実装が進んだら採点し直す。
