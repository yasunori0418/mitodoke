# 台帳の書式

決まった語を item にするまで溜めておく表。`term-record` が書き、`term-apply` が読む。書式の正本はこのファイル。

## 置き場所

既定は、リポジトリのルートの `tmp-agents/terms.md`。`tmp-agents/` は git の管理外で、worktree からも同じ実体を読む。
1 つのリポジトリに台帳は 1 つで、どの作業で決まった語も同じ表に足す。`/term-apply` は引数で別のパスを受け取れる。

ファイルが無ければ、次の見出しと表の先頭 2 行を書いて作る。

## 表

```markdown
# 用語の台帳

| slug | name | name_ja | avoid | section | 定義の手がかり | 状態 |
| --- | --- | --- | --- | --- | --- | --- |
| reach-rate | reach rate | 到達率 | カバー率 | inspection | 上流の item のうち、下流まで辿れるものの割合。分母は規範の型ごと | 未起票 |
| item | item | | アイテム | graph | グラフの 1 つの節。frontmatter に id と type を持つ Markdown | 起票済み（feat/term-skills） |
```

| 列 | 書くこと |
| --- | --- |
| slug | item のファイル名（`<slug>.md`）。英小文字・数字・ハイフン。`index` は使えない。既存の item と同じ slug は、その item の変更を表す |
| name | 英語の正名。型やフィールドの名前なら `snake_case` の識別子、それ以外は小文字の語句 |
| name_ja | 日本語の正名。英語のまま使う語では空欄 |
| avoid | 執筆で使わない綴り。複数あれば `、` で区切る。無ければ空欄。綴りだけを書き、理由は「定義の手がかり」に書く |
| section | 索引の節。`docs/model.yaml` の `ubiquitous_term` の `section` の enum の値 |
| 定義の手がかり | 定義に書く内容の要点、根拠にする文書、避ける理由と言い換え。item の本文の材料になる |
| 状態 | `未起票`、または `起票済み（<ブランチ名>）` |

## 規則

- `avoid` には、ほかの語の正名として正しく使う綴りを入れない。入れると検査が誤検出する。
- セルの中で `|` を使わない。
- 起票済みの行は消さない。同じ語を二重に起こさないための記録になる。
- 決まった語の正名を後で変えたら、行を書き換える。起票済みの語なら、同じ slug で `未起票` の行を足す。
